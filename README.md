# Majestic Orlando Family Bot

Discord-бот семьи Kraken для Majestic RP Orlando.

Иконки интерфейса: [Icons8](https://icons8.com) — стиль Liquid Glass.

Версия сборки: **1.914.0208**

## Возможности

- анкеты на вступление;
- личный кабинет с профилем, обращениями и AFK-системой;
- ранги и история их изменений;
- варны и история действий;
- баланс и операции MP;
- автоматическая обработка MP-отчётов;
- приём и модерация откатов с капта через `/capts`;
- профиль участника;
- список неактивных участников;
- список участников, готовых к повышению, через `/info`;
- массовое перемещение между голосовыми каналами через `/move`.

## Хранение данных

Все рабочие данные хранятся только в MySQL. Локальные JSON-файлы не используются.

Рабочие таблицы:

- `users` — текущие профили;
- `recruitment_settings` — отдельные строки Capt и RP со статусом и временем обновления;
- `tickets` — заявки с категориями `application` и `support`;
- `warning_logs` — история варнов;
- `rank_logs` — история рангов;
- `mp_point_transactions` — заявки, начисления и списания MP.
- `afk_sessions` — активные игровые AFK-сессии с сохранённым временем завершения.
- `capt_replay_window` — состояние приёма откатов с капта (`/capts`): открыт ли приём, когда открыт, счётчик открытий и ветки на очистку.

Номера новых заявок имеют формат `<тип>-<10 цифр>`, например
`A-5831049276`.

Бот работает на Railway: сервис MySQL и сервис бота живут в одном приватном
окружении (`*.railway.internal`), поэтому подключение к базе идёт без TLS.
Если переменная `MYSQL_SSL_CA_PATH` задана, соединение вместо этого выполняется
по TLS с обязательной проверкой указанного CA-сертификата — это нужно только
для сторонних провайдеров с публичным доступом к базе, не для Railway.

Обязательные переменные `.env` (на Railway задаются как Variables сервиса):

```env
DISCORD_TOKEN=
DISCORD_CLIENT_ID=
DISCORD_GUILD_ID=

MYSQL_HOST=
MYSQL_PORT=3306
MYSQL_USER=
MYSQL_PASSWORD=
MYSQL_DBNAME=

# Опционально: путь к CA-сертификату (относительно корня проекта) — включает
# обязательный TLS. Не задавайте на Railway.
MYSQL_SSL_CA_PATH=
```

## Установка и запуск

Требуется Node.js **20.9.0 или новее**.

```bash
npm install
npm run register
npm start
```

Продакшен — Railway, подключённый к GitHub-репозиторию: пуш в `master`
запускает автосборку и передеплой сервиса `kraken-bot` автоматически, вручную
ничего перезапускать не нужно. Логи — `railway logs --service kraken-bot`.

## Обновление панелей

Бот публикует недостающие панели и обновляет существующие автоматически после запуска.

Панель личного кабинета содержит три кнопки:

- «Личный кабинет»;
- «Создать обращение»;
- «AFK-система».

В канале `1291543297747194010` бот автоматически поддерживает административную
панель с разделами «Варны», «Ранги», «Баллы», «Составы», «AFK» и «Информация».
Все кнопки серые, а содержимое разделов показывается только нажавшему участнику
руководства.

После нажатия «Создать обращение» открывается форма с обязательным выпадающим
списком типа заявки и полем для подробного описания. Тип сохраняется в
`tickets.request_type`, описание — в `tickets.details`. Минимальная длина
описания — 2 символа; при каждом открытии формы выбор типа начинается заново.

## Команда `/info`

Показывает участников, готовых к повышению, с пагинацией:

- 1 → 2 ранг — фамилия Kraken;
- 2 → 3 ранг — 75 MP;
- 3 → 4 ранг — 150 MP;
- 4 → 5 ранг — 300 MP;
- 5 → 6 ранг — 450 MP;
- 6 → 7 ранг — 600 MP.

Контракты, взносы, разговор с лидерами и прочие дополнительные условия
администрация проверяет вручную.
С 7 ранга и выше повышение выдаётся только вручную, по решению основателей
или по доверию — MP для этого больше не учитываются.

В `recruitment_settings` Capt и RP хранятся отдельными строками со своим статусом и временем обновления.

Перед обработкой сообщения, реакции или события участника (вход/выход/смена
ролей) бот заново загружает актуальные данные из MySQL. Команды, кнопки и формы
используют кеш в памяти без блокирующего похода в базу (чтобы не рисковать
3-секундным окном ответа Discord), а сам кеш дополнительно обновляется фоном
каждые 60 секунд. Поэтому ручные изменения в панели базы данных применяются без
перезапуска бота, но не мгновенно — с задержкой до минуты.

## Команда `/move`

Доступна только ролям руководства из `leadershipRoleIds`.

- `from` — исходный голосовой канал;
- `to` — целевой голосовой канал.

Боту необходимы разрешения `Move Members`, `View Channel` и `Connect`.

## Управление заявками

В заявках на вступление и обычных обращениях используются кнопки управления.
В обычном обращении доступны «Закрыть» и «Передать»: закрытие
сразу назначает нажавшего администратора ответственным и устанавливает конечный
статус «Закрыто». Передача доступна только после взятия заявки сообщением или реакцией.
В заявках на вступление остаются «Принять», «Отклонить» и «Передать».

Панель вступления и карточки заявок используют Discord Components V2. Остальные
панели и журналы используют обычные Discord-эмбеды.

Кнопка «Составы» в административной панели переключает Capt, RP или оба состава
после личного подтверждения. Состояния Capt- и RP-набора хранятся в MySQL и отображаются
в панели. После отклонения заявку на вступление можно подать повторно через 10 дней.

При принятии заявки в любой состав (RP или CAPT) выдаётся одна и та же роль
Verified — `1265995505524015245`. Отдельных ролей для RP- и CAPT-состава больше
нет. Просматривать и обрабатывать заявки и обращения, а также
управлять ботом через административную панель, может любой участник с ролью из
`config.json → leadershipRoleIds` (High Staff и выше) — их же бот упоминает при
создании новой заявки или обращения.

## Варны

При получении третьего активного варна бот снимает с участника все роли на
Discord-сервере (исключения из фамы не происходит). Бан, специальная роль
ограничения и система апелляций не используются.

## Управление

Роли руководства и рангов настраиваются в `config.json`. Секреты и реквизиты
MySQL должны храниться только в `.env`.
